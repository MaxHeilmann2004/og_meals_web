# OG Meals

An unofficial meal-planning app created by an Otto Group employee for other employees. OG Meals presents canteen data from official Otto Group services in a mobile-friendly, independently prepared interface.

OG Meals is a private project. It is neither operated nor commissioned by the Otto Group.

## Requirements

- Node.js 24 (see `.node-version`)
- pnpm 11.22.0

## Setup

Install dependencies:

```bash
pnpm install
```

Start the development server at `http://localhost:3000`:

```bash
pnpm dev
```

## Production

Create a production build:

```bash
pnpm build
```

Preview it locally:

```bash
pnpm preview
```

## Meal plan image

`GET /api/meal-plan-image` returns a PNG of the reduced meal plan (Elbe and bonprix; Grill, The Original, F&T Vegan, Pasta, Pizza, Heimatküche, Vital, Live-Counter). The selection lives in `app/config/mealPlanImage.ts`.

Authenticate with a valid verification token, either as `x-verification-code` header or as `?verification=` parameter. If neither is given, the `og-meals-verification` cookie of the browser session is used, so the endpoint can be opened directly in a verified browser. Optional query parameters:

| Parameter | Default | Description |
| --- | --- | --- |
| `date` | today (Europe/Berlin, weekends → Monday) | `YYYY-MM-DD` |
| `width` | `1300` | Image width in px (320–2400); the column count follows the width |
| `scale` | `1` | Pixel density factor (1–3) |
| `theme` | `light` | `light` or `dark` |
| `studentPrices` | off | `1` shows student prices |
| `inline` | off | `1` displays the image instead of downloading it |

The image is built from the Vue components in `app/components/meal-plan-image/`. The internal page `/__image/meal-plan` is rendered through Nuxt SSR, converted with Satori and rasterized with resvg, so no browser is needed. Satori does not support CSS variables or stylesheets, so these components use inline styles and the colors in `app/config/mealPlanImageTheme.ts`. The bundled font is Outfit (OFL, see `server/assets/fonts`). Results are cached in memory for five minutes.

Every request is logged with a short request ID (`[meal-plan-image] <id> ...`): verification, queue, backend meals request, SSR page, each image download and resize, Satori and resvg, with slow (>= 1 s) and failed images as warnings. The same step durations are returned in the `Server-Timing` response header, which the browser devtools show on the Network tab.

## Configuration

The verification code is the upstream proxy key, extracted by the upstream service from its client-side JavaScript bundle. It is publicly inspectable and should not be treated as a secret. The Nuxt server validates submitted codes by calling the backend's `GET /verification` endpoint with the `X-Verification-Code` header; that endpoint returns `{ "configured": boolean, "authenticated": boolean }`. Users can enter the code manually or scan the Kochwerk QR code; its decoded text is submitted verbatim as the verification code. Camera access requires a supported browser and secure context (HTTPS); manual entry remains available as a fallback.

After successful validation, Nuxt stores the user-supplied code in an HttpOnly, same-site cookie with a rolling 400-day persistence window. The cookie is refreshed whenever the backend confirms that the code is still valid and cleared when the backend rejects it. The code can also be supplied once as `?verification=<code>`; the server checks it and redirects to a clean URL. If backend verification cannot be established, access remains closed.

The Nuxt API proxy forwards the cookie value to the backend in the `X-Verification-Code` header, where protected API routes must validate it. Set `NUXT_PUBLIC_API_BASE_URL` to override the backend URL (defaults to `https://3b-meals.mh-home.net`).

The following public environment variables are also supported:

```bash
NUXT_PUBLIC_TURNSTILE_SITE_KEY=
NUXT_PUBLIC_PLAUSIBLE_DOMAIN=
```

Plausible events are sent to the self-hosted instance at `https://insights.matix-media.net`.
